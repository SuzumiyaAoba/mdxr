`mdxr` はレンダリング・プレビュー・オーサリングのための単一 CLI です。`npx @suzumiyaaoba/mdxr <command>` で都度実行するか、グローバルインストール（`npm i -g @suzumiyaaoba/mdxr`）して使います。

## mdxr --version

この CLI 呼び出しで解決されるパッケージのバージョンを表示します。`-v` は短縮形です:

```sh
mdxr --version
mdxr -v
```

## mdxr check [path]

単一文書またはディレクトリ内の `.md`・`.markdown`・`.mdx` 文書を、HTML を書き出さずに検証します。パスを省略すると `.mdxr` を使います。

```sh
mdxr check                            # .mdxr/ を一括検証
mdxr check plan.mdx                   # 単一文書を検証
mdxr check ./reports --format json    # 構造化した診断を出力
mdxr check ./reports --strict         # 警告も失敗扱いにする
mdxr check plan.mdx --render          # 独自コンポーネントと描画も検証
cat plan.mdx | mdxr check -           # stdin は - を明示
```

通常は文書の JavaScript・プロジェクト設定・React コンポーネントを実行せずに解析します。コンポーネント名、スキーマ付きの属性、必須属性、値、禁止された JavaScript、ローカルリソース、CodeFile の行範囲、Include のセクション・循環参照、引用・相互参照を検査します。`sttaus="done"` のような未知の属性は、候補付きの警告になります。shadcn など任意の属性を通す空のスキーマには、属性名の制限を適用しません。`aria-*`・`data-*`・共通の JSX 属性も許可します。

埋め込むファイルや通常のローカルリンクの欠落はエラーです。FileRef などの参照先の欠落は、未作成のファイルを計画に記載できるよう警告にします。外部 URL とサイトのルートから始まる URL は取得・検査しません。Markdown リンクのフラグメントは、ローカルの見出しと明示的な ID に照合します。構文解析できる文書では独立した診断をまとめ、構文エラーがある文書の後も検査を続けます。ビルド・依存ディレクトリと `.mdxr/history` は除外し、シンボリックリンクはたどりません。

`--render` は文書のディレクトリにある `mdxr.config.*` と独自コンポーネントを読み込み、静的検査にエラーがなければサーバー描画も検証します。この指定では信頼するプロジェクト設定とコンポーネントのコードを実行しますが、文書内の JavaScript は引き続き禁止です。レンダラーのキャッシュを使う場合がありますが、HTML ファイルは書き出しません。

| フラグ | 説明 |
| --- | --- |
| `--format <format>` | 診断形式: `text`（デフォルト）または `json` |
| `--strict` | 警告もエラーと同様に失敗の終了コードにする |
| `--render` | 独自コンポーネントを読み込み、描画も検証する |

JSON は `ok`・`files`・`errors`・`warnings` と `diagnostics` 配列を含みます。各診断には `file`・`line`・`column`・`code`・`severity`・`message` があり、候補があれば `suggestion` も返します。エラーがある場合の終了コードは 1 です。警告だけの場合は、`--strict` の指定時に限り 1 になります。

## mdxr library [dir]

ディレクトリ内の Markdown・MDX ドキュメントを一覧・横断検索します。ディレクトリを省略すると `.mdxr` を使います。

```sh
mdxr library                         # .mdxr を表示
mdxr library ./docs -p 3738 --open   # 別のディレクトリを表示
```

`.md`、`.markdown`、`.mdx` を再帰的に一覧します。タイトルは frontmatter の `title`、最初の見出し、ファイル名の順に決まり、frontmatter の `status` で絞り込めます。更新日はファイルの更新日時です。

タイトル・本文・相対ファイルパスを検索します。半角・全角空白を区切りとした AND 検索で、たとえば `かたろぐ ＡＰＩ` は両方の語を含む文書を探します。日本語は部分一致します。Unicode NFKC 正規化と英字の小文字化で、全角・半角、濁点付き半角カナ、英字の大小文字などの表記ゆれを吸収します。ひらがなとカタカナも同一視します。漢字の読み推定、同義語展開、形態素解析は行いません。IME 変換中は検索を保留し、入力確定後に検索します。

status で絞り込み、関連度・更新日・タイトル順に並べ替えられます。結果には一致箇所の近くの抜粋を表示し、一致した語をハイライトします。**更新** を選ぶと追加・変更・削除を再索引します。UI 言語はブラウザーの言語から自動選択するか手動で切り替えられます。選択した UI 言語と自動・ライト・ダークのテーマは、このライブラリと同じオリジンに保存されます。

文書を開くと、既存のライブプレビュー・ワークスペースを新しいタブに表示します。版履歴も利用できます。ライブラリとプレビューは loopback で待ち受けます。索引作成では文書内の JavaScript やプロジェクト独自コンポーネントを実行しません。`node_modules`、`dist`、`.git`、`.mdxr-cache`、`storybook-static`、`.mdxr/history` は除外し、シンボリックリンクをたどりません。`mdxr serve` は同じライブラリにエージェントチャットと、指定した文書を直接開く機能を追加します。

各行から文書を削除できます。UI で確認すると対象の文書ファイルだけを完全に削除し、assets と親ディレクトリは残します。

| フラグ | 説明 |
| --- | --- |
| `-p, --port <port>` | 待ち受けポート（デフォルト `3737`）。使用中の場合は次の空きポートを利用 |
| `--open` | サーバー起動後にデフォルトブラウザーでライブラリを開く |

## mdxr render

`.mdx` ドキュメント（ファイル引数または stdin）をスタンドアロン HTML ファイルにレンダリングします。

```sh
mdxr render plan.mdx                  # → plan.html
mdxr render plan.mdx -o out.html      # 出力先を指定
cat plan.mdx | mdxr render > out.html # stdin → stdout
mdxr render plan.mdx --open           # plan.html をブラウザで開く
mdxr render plan.mdx --no-hydrate     # クライアントバンドルなしの静的 HTML
mdxr render plan.mdx --format json    # 機械可読なエラー出力
```

| フラグ | 説明 |
| --- | --- |
| `-o, --out <path>` | 出力パス。デフォルトは `<file>.html`。stdin 入力または `-` 指定時は stdout |
| `--format <format>` | エラー出力形式: `text`（デフォルト）または `json` |
| `--no-hydrate` | クライアントのハイドレーションバンドルなしで静的 HTML を出力 |
| `--open` | 出力ファイルをデフォルトブラウザで開く。出力ファイルが必要 |

:::note
ステートフルなコンポーネント（`Tabs`、`Accordion`、`Switch`、カンバンの `<Board>` など）は、インライン化されたクライアントバンドルによってブラウザ上でハイドレートされます。ハイドレート対象のコンポーネントを使わないドキュメントではバンドル自体が省略されるため、純粋な Markdown ドキュメントは軽量なままです。`--no-hydrate` を指定すると完全に無効化できます。
:::

エラーは `file:line:col` 付きで報告されるため、エージェント（あるいは人間）がソースを修正して再実行できます。`--format json` は同じメッセージを機械可読な出力に包みます。

生成された HTML では[レビュー注釈](/ja/annotations)を利用できます。文章や図にコメントし、Coding Agent に渡す Markdown をコピーできます。`--no-hydrate` でも利用できます。

## mdxr serve

`.mdxr/` 配下の Markdown・MDX 文書をまとめて配信します。パスを省略すると、`.mdxr/` がなければ空のディレクトリを作成します。別のディレクトリを指定することもできます。各文書はライブリロード付きのワークスペースで開きます。

```sh
mdxr serve                           # .mdxr/ を http://localhost:3737 で配信
mdxr serve .mdxr/ --open .mdxr/20260930170000-plan/index.mdx
mdxr serve ./reports -p 8080 --open ./reports/plan.mdx
mdxr serve --open                    # ディレクトリの一覧を開く
cat plan.mdx | mdxr serve - --open   # stdin は - を明示
```

| フラグ | 説明 |
| --- | --- |
| `-p, --port <port>` | 待ち受けポート（デフォルト `3737`）。使用中の場合は次の空きポートを利用 |
| `--open [file]` | 指定した文書を直接開く。ファイルを省略するとディレクトリの一覧を開く |
| `--agent <agent>` | `codex` または `claude` 用のローカルチャットを表示 |
| `--server <url>` | Codex App Server の接続先。`unix:///absolute/path` または `ws://...` を指定（`--agent codex` が必要） |
| `--session <id>` | 既存の Codex スレッドにメッセージを送信（`--agent codex` が必要） |

`--open` のファイルパスは作業ディレクトリから解決し、絶対パスも利用できます。ブラウザではその文書を直接開き、プレビューの URL に配信ディレクトリからの相対パスが含まれます。`mdxr serve .mdxr/20260930170000-plan/index.mdx --open` のようにファイルを指定して起動した場合も、含まれる `.mdxr/` 全体を配信してその文書を開きます。`.mdxr/` 外のファイルでは、その親ディレクトリを配信します。

ウォッチャーは開いた文書ごとのレンダリング依存関係をたどります — `theme` の CSS ファイルとそのインポートも変更でプレビューが再読み込みされます。`--agent` を指定すると、各文書のワークスペースに AI Elements ベースのチャットパネルが表示されます。**コメント** でレンダリング済みの内容にコメントを付け、同じチャットへ直接送信できます。文書のレンダリングとエージェントセッションの起動は、一覧から文書を選んだときに行います。

ウォッチャーは MDX の変更を検出してローカルに版を保存します。版の選択メニューから過去の版をレンダリングしたり、**Raw MDX** でソースを確認したり、**Diff** で別の版と比較したりできます。履歴は `.mdxr/history/` に保存されます。履歴の保存と閲覧はローカルで完結し、API トークンは不要です。

ワークスペースの **Export HTML** を選び、内容を指定して **Download HTML** を押すと、単一の HTML をダウンロードできます。

- **Document only（本文のみ）**: 現在の表示と入力値を保持します。コメント、レビュー操作、会話、版の記録は含まず、会話・履歴のデータも取得しません。
- **Document and review（本文＋レビュー）**: 現在のコメント、セクションのレビュー状況、回答を含みます。会話、未送信の下書き、コメントのコピー・送信履歴、保存版の MDX と差分は、表示と埋め込み JSON の両方から除外します。
- **All records（全記録）**: デフォルトです。本文、会話、コメント、下書き、セクションのレビュー状況、保存済みの全 MDX 版と差分を含みます。

どの形式でも画像とスタイルシートを本文に埋め込み、外部リソースを取得できない場合は省略せずエラーを表示します。サーバーを起動せずにローカルで開けます。Escape または **Cancel** で、書き出さずにダイアログを閉じられます。

`--agent` で配信ディレクトリ内の各文書のチャットを有効にします。すでに起動している Codex TUI セッションにメッセージを送るには、そのスレッド ID を指定します。既定ではローカル Codex daemon のソケットに接続し、TUI セッションを動かしたままスレッドにメッセージをキューイングします。

```sh
mdxr serve .mdxr/ --agent codex --session <thread-id> --open .mdxr/20260930170000-plan/index.mdx
```

Codex が処理中のメッセージはキュー待ちとして表示されます。Codex がメッセージを処理すると、回答が MDX プレビューに表示されます。特定の daemon ソケットまたは WebSocket App Server を使う場合は、接続先を `--server` に指定します。

```sh
mdxr serve .mdxr/ --agent codex --server unix:///absolute/path/to/app-server.sock --session <thread-id>
mdxr serve .mdxr/ --agent codex --server ws://127.0.0.1:4500 --session <thread-id>
```

`--session` を省略した場合、`.mdxr/sessions.json` にこのドキュメントの Codex スレッド ID が保存されていれば、そのスレッドを使います。保存されていなければ、新しいスレッドを開始します。

Claude チャットでは、mdxr が長寿命の Claude Agent SDK セッションを管理します。

```sh
mdxr serve .mdxr/ --agent claude --open .mdxr/20260930170000-plan/index.mdx
```

Claude のセッションは mdxr が所有し、外部の Claude CLI で開始したセッションには接続しません。`--session` は Codex 専用です。

プレビューにはツール承認 UI がないため、承認が必要な操作は拒否されます。Claude は `dontAsk` 権限モードで実行されます。

ドキュメントとセッションの対応および会話履歴は、作業ディレクトリの gitignore 対象である `.mdxr/sessions.json` に保存されます。`--agent` はディレクトリ・ファイルのどちらでも利用でき、stdin は使えません。エージェントの回答は Markdown として表示し、JSX と生 HTML は実行しません。

## mdxr text

`.mdx` ドキュメントをプレーンな Markdown に変換します。すべてのコンポーネントが ASCII/テキスト表現 — ステータス付きチェックボックスリスト、ブロックバーチャート、GFM テーブル、`<details>` 開閉ブロック — に置き換わるため、任意の Markdown ビューアやターミナルで読めます。

```sh
mdxr text plan.mdx                    # → plan.txt.md
mdxr text plan.mdx -o plan.md         # 出力先を指定
cat plan.mdx | mdxr text > plan.md    # stdin → stdout
```

インタラクティブ専用のウィジェット（ダイアログ、メニュー、shadcn 系）はテキスト内容にフォールバックし、未知のコンポーネントは stderr に警告を出しつつ子要素をそのまま保持します。

| フラグ | 説明 |
| --- | --- |
| `-o, --out <path>` | 出力パス。デフォルトは `<file>.txt.md`。stdin 入力または `-` 指定時は stdout |

## mdxr catalog

ドキュメントで利用可能なコンポーネント — ビルトインに加えて `mdxr.config.ts` で定義されたプロジェクト固有コンポーネント — を一覧します。エージェントは `--json` を名前と属性の機械可読な信頼ソースとして使います。

```sh
mdxr catalog                          # 人間向け一覧
mdxr catalog --json                   # 名前・メタ情報・オーサリング規約
mdxr catalog --dir ./my-project       # 別プロジェクトの設定を読む
```

| フラグ | 説明 |
| --- | --- |
| `--json` | 機械可読な JSON を出力 |
| `--dir <dir>` | `mdxr.config.ts` を読み込むプロジェクトディレクトリ（デフォルトは cwd） |

## mdxr init

Codex と Claude 向けの mdxr オーサリング指示をインストールし、それぞれの指示ファイルから参照できるようにします。デフォルトのインストール先はホームディレクトリです。[エージェントのセットアップ](/ja/agent-skill) も参照してください。

```sh
mdxr init                              # ホームディレクトリの Codex + Claude
mdxr init --tool codex                 # Codex のみ
mdxr init --tool claude --local        # このプロジェクトの Claude のみ
mdxr init --tool all --local           # このプロジェクトの Codex + Claude
mdxr init --global                     # ホームディレクトリへの導入を明示
mdxr init --force                      # 生成した指示と参照を更新
mdxr init --skill                      # 同梱の Agent Skill をインストール
```

| フラグ | 説明 |
| --- | --- |
| `--tool <tool>` | 指示のインストール時は `codex`、`claude`、`all`（デフォルト）。スキルでは `agents`（デフォルト）、`claude`、`devin`、`all` |
| `--local` | ホームディレクトリではなく現在のプロジェクトに指示をインストール |
| `--global` | ホームディレクトリにインストール（デフォルトの範囲） |
| `--force` | mdxr の指示と参照を更新。`--skill` と併用するとスキルディレクトリを置き換え |
| `--skill` | 指示ファイルの代わりに同梱の Agent Skill をインストール。スキルのデフォルト先はプロジェクト |

グローバルインストールでは、`$CODEX_HOME/MDXR.md`（`CODEX_HOME` 未設定時は `~/.codex/MDXR.md`）と `$CODEX_HOME/mdxr/references/`、および `~/.claude/` 以下の同等ファイルを作成します。`$CODEX_HOME/AGENTS.md` に Codex 用ファイルを読む指示を追加し、Claude の `~/.claude/CLAUDE.md` から `@./MDXR.md` を読み込みます。ローカルインストールでは、プロジェクトに `.codex/MDXR.md` と `.claude/MDXR.md` を作成し、ルートの `AGENTS.md` と `CLAUDE.md` から参照します。Claude の `CLAUDE.md` では `@./.claude/MDXR.md` を読み込みます。また、`.mdxr/` をプロジェクトの `.gitignore` に追加します — グローバルの git 除外ファイル（`core.excludesFile`、通常は `~/.config/git/ignore`）が `.mdxr/` をカバー済みの場合は追加しません。`--force` は生成した指示と参照を更新し、エージェント設定の他の内容を保持します。

配布プロンプトは、エージェントに記録された版と作業で使う CLI の `--version` を照合させます。不一致時は両方の版を伝え、同じ CLI で元の `--tool` と `--local`/`--global` の範囲を保ったまま `mdxr init --force` で更新する方法を案内します。Skill の場合は `--skill` も維持します。詳しくは[エージェントのセットアップ](/ja/agent-skill)を参照してください。
