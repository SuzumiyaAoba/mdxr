mdxr ドキュメントは `.mdx` ファイルです。Markdown の本文に [カタログ](/ja/components) の JSX コンポーネントを混ぜて書きます。ドキュメントは**プログラムではなくデータ** — レンダラーが決定論的にコンパイルするため、モデルがマークアップ・スタイル・スクリプトを出力することはありません。

## ルール

- **JavaScript は書けません。** `import`/`export` 文と `{expressions}` は拒否されます。
- **属性は文字列のみ。** `<Step status="done">` と書き、`status={...}` は使えません。
- **`children` は Markdown。** コンポーネントと本文は自由にネストできます。
- **本文はプレーンな Markdown を優先。** 構造が意味を持つ場面でのみコンポーネントを使います。

違反は `file:line:col` 付きのエラーでレンダリングに失敗します — ソースを直して再実行してください。

## Frontmatter

YAML frontmatter がドキュメントヘッダーを駆動します:

```mdx
---
title: Renderer rewrite
status: doing        # todo | doing | done | blocked
date: 2026-09-10
updated: 2026-09-16
owner: "@suzumiyaaoba"
version: v3
editor: cursor       # エディタリンクのスキーム。mdxr.config.ts を上書き
---
```

`title` があれば、mdxr はドキュメントヘッダー — ステータスバッジとメタ行 — を自動で描画します。本文がすでに `<Plan>` 系のルートで始まる場合（そちらが同じ props を自分で持つため）はスキップされます。

## Markdown 規約はコンポーネントにコンパイルされる

書くのは Markdown、レンダラーがショートハンドをカタログコンポーネントに変換します:

| 書くもの | 得られるもの |
| --- | --- |
| `:::note` / `:::warning` / `:::decision` | `<Callout>` |
| `:::goal` / `:::nongoal` / `:::question` / `:::answer` | ゴール / 非ゴール / 未解決の問い / 結論のコールアウト |
| `:::phase{title="…" status="doing"}` | ステータスバッジ付き `<Phase>` 見出し |
| `> [!NOTE]` GitHub アラート | `<Callout>` |
| `- [ ]` / `- [x]` | スタイル付きタスクリスト |
| `` ```ts title="src/x.ts" `` | ハイライト済みコードブロック + ファイル名バー |
| `` ```diff `` / `` ```patch `` | ファイルごとの構造化 diff カード |
| `` ```mermaid `` | レンダリング済みダイアグラム |
| `` ```console `` | ターミナルトランスクリプト |
| `$…$` / `$$…$$` | KaTeX 数式 |
| `` `src/x.ts` ``（実在するファイル） | エディタリンク付き `<FileRef>` チップ |

`:::` ディレクティブ構文はほとんどのコンテナコンポーネントを包みます — `:::findings`、`:::gantt`、`:::barchart`、`:::board`、`:::tests` など。全マッピングは [カタログ](/ja/components)、機械可読版は `mdxr catalog --json` を参照してください。

## セクションごとの閲覧

`##` 見出しのあるドキュメントでは、生成した HTML とライブプレビューに **Document / Pages** の切り替えが表示されます。既定の **Document** は全文を続けて表示します。**Pages** はセクションを 1 ページずつ表示し、左側の垂直タブに見出しを並べます。最初の `##` より前の本文は **Overview** タブに入り、`###` 以下の見出しは親ページに含まれます。

分割対象はドキュメント直下、およびルートの `<Plan>` 直下にある Markdown の見出しです。他のコンポーネントや引用内の見出しでは分割しません。設定の追加や出力ファイルの分割は不要です。

タブは ↑ / ↓、Home、End キーでも移動できます。見出しへのリンクは対象ページを開き、ブラウザーの戻る・進むでもページ間を移動できます。表示を切り替えても、コンポーネントやフォームの状態は保たれます。ローカルストレージが利用可能なら表示モードを記憶します。狭い画面では垂直タブを本文の上に表示します。印刷は常に全文が対象で、JavaScript が無効の場合も全文を表示します。

## セクションごとの確認状態

ドキュメント直下の各 `##` 見出しと同じ行の右端に、**Not reviewed（未確認）／Reviewed（確認済み）** ボタンが表示されます。狭い画面では、必要に応じてボタンが見出しの下へ折り返します。内容に問題がないことを確認したら **Reviewed** にし、再度押すと未確認に戻せます。Document と Pages の両方で利用でき、`--no-hydrate` で出力した HTML でも動作します。Pages のサイドバーには各セクションの状態と確認済み件数も表示されます。Tab でボタンへ移動し、Space または Enter でも切り替えられます。

確認対象は次のドキュメント直下の `##` までで、`###` 以下も含みます。最初の `##` より前の Overview、引用内やコンポーネント内の見出しには個別の状態を付けません。ルートの `<Plan>` 直下にある `##` は対象です。

状態はブラウザーのローカルストレージに文書パスごとに保存され、同じオリジンのタブ間で同期されます。再読み込み後も復元されますが、MDX 自体への書き込みや、HTML の共有による状態の共有は行いません。内容が変わったセクションは未確認に戻ります。他の箇所の編集や行番号の変化だけなら確認済み状態を保ちます。ストレージを利用できない場合も、そのページを開いている間は切り替えられます。変更を保存できなかったときだけ、操作したボタンのそばに **Not saved（未保存）** を表示します。印刷時には確認ボタンを表示しません。

## エディタリンク

`path` を持つコンポーネント — `<FileRef>`、`<SymbolRef>`、`<File>`、`<TraceFrame>`、`<FlowStep>`、`<Change>` — とコードブロックのファイル名ヘッダーは、ファイルがディスク上に存在する場合 `vscode://file/…` リンクになります（ドキュメントからの相対パスで解決）。インラインコードも同様です: `` `src/mdx.ts:40-52` `` は実在ファイルに解決できれば `<FileRef>` に自動変換され、`/` を含まない素の `mdx.ts` はプレーンなコードのままです。

スキームは `mdxr.config.ts` の `editor` かドキュメントの frontmatter で選びます: `vscode`（デフォルト）、`cursor`、`zed`、`vscode-insiders`、`windsurf`、`sublime`、`textmate`、`idea`、`"myed://open?f={path}&l={line}"` のような `{path}`/`{line}` カスタムテンプレート、または無効化する `none`。コンポーネントの `href="…"` は URL を完全に上書きします。

## レンダリングパイプライン

同じソースから 3 つの出力が得られます:

| コマンド | 出力 |
| --- | --- |
| `mdxr render` | スタンドアロン HTML — インライン Tailwind CSS、シンタックスハイライト、ハイドレーションバンドル |
| `mdxr serve` | ライブリロード付きブラウザプレビュー |
| `mdxr text` | ASCII 表現のコンポーネントを含むプレーン Markdown |

すべてのドキュメントで Tailwind CSS がレンダリング時に生成されます — ドキュメント（とそのコンポーネント）が実際に使うユーティリティだけが出力されるため、サイズは小さく保たれます。
