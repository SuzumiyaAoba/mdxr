mdxr includes detailed authoring instructions and a component reference catalog for coding agents. `mdxr init` installs these files for Codex and Claude and adds a reference from each agent's global instructions. For projects that use the [Agent Skills format](https://github.com/vercel-labs/skills), the bundled skill is also available with `mdxr init --skill`.

## Install instructions

By default, `mdxr init` installs instructions for Codex and Claude in your home directory:

```sh
mdxr init                         # Codex + Claude, in your home directory
mdxr init --tool codex            # Codex only
mdxr init --tool claude --local   # Claude only, in this project
mdxr init --global                # explicitly install into your home directory
mdxr init --force                 # refresh generated instructions and references
```

The global install creates `$CODEX_HOME/MDXR.md` (or `~/.codex/MDXR.md` if `CODEX_HOME` is unset) and `$CODEX_HOME/mdxr/references/`, plus matching files under `~/.claude/`. It adds a read instruction to `$CODEX_HOME/AGENTS.md`; `~/.claude/CLAUDE.md` imports `@./MDXR.md`. Pass `--local` to write `.codex/MDXR.md` and `.claude/MDXR.md` in the current project and reference them from the root `AGENTS.md` and `CLAUDE.md`. A local install also adds `.mdxr/` to `.gitignore`, where agents save documents and rendered HTML — skipped when your global git excludes file already covers it. `--force` refreshes generated instruction files and references while preserving the rest of your config files.

If a directory also has an `AGENTS.override.md`, add the generated Codex read instruction there too; Codex gives it precedence over `AGENTS.md` in the same directory.

## Install the Agent Skill

Use `--skill` to install the bundled skill into a supported skills directory:

```sh
mdxr init --skill                         # → .agents/skills/mdxr/
mdxr init --skill --tool claude           # → .claude/skills/mdxr/
mdxr init --skill --tool all --global     # all supported skills in your home directory
```

The skill install defaults to the project directory and supports `agents` (the default), `claude`, `devin`, or `all` with `--tool`. Add `--global` to install under your home directory. `--force` replaces the skill directory.

Alternatively, install it from the repo with the [`skills` CLI](https://github.com/vercel-labs/skills):

```sh
npx skills add Suzumiyaaoba/mdxr --skill mdxr
# add -g for a global install, or -a claude-code to target a specific agent
```

## Use it

After either setup, ask for a deliverable:

> Write an implementation plan for the auth feature and render it to HTML with mdxr.

By default, new documents use `.mdxr/yyyyMMddhhmmss-<name>.mdx`, with a zero-padded 14-digit local creation time in 24-hour format (for example, `.mdxr/20260929140530-auth-plan.mdx`). A filename or file path you provide takes priority. If you specify only a directory, save the document there with a timestamped filename. Preview it with `mdxr serve .mdxr/20260929140530-auth-plan.mdx`.

Plans, reports, reviews, investigation summaries, release notes, and postmortems all work.

## What the skill contains

| File | Contents |
| --- | --- |
| `SKILL.md` | The workflow — write `.mdx`, `render`, `serve`, `text` — the authoring rules, and a syntax cheatsheet |
| `references/components.md` | The catalog index: what every component does, grouped by document type |
| `references/components/*.md` | Per-group detail files with full signatures and examples — the agent reads only what the document needs |
| `references/extending.md` | How to register project-defined components via `mdxr.config.ts` |

The skill teaches a read-on-demand pattern: the agent consults the index first, then loads only the detail files the document actually uses — so a plan doesn't pay the context cost of the chart reference.

## How agents stay honest

- Documents carry no JS — `import`, `{expressions}`, and non-string attributes fail the render with `file:line:col` errors the agent can self-correct.
- `mdxr catalog --json` gives the agent the live component set, including your project-defined components.
- `mdxr render --format json` returns machine-readable errors for automated retries.
