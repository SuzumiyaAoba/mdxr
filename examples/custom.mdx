## FeatureCard — composing built-ins

`mdxr/components` re-exports the catalog, so custom components wrap `<Icon>`,
`<StatusBadge>`, `<Callout>`, … instead of re-styling from scratch. Reusing
`STATUSES` keeps the `status` picklist identical to the built-in one.

## Prop validation

Schemas turn typos into document errors with `file:line:col` instead of
silent mis-render. `<FeatureCard status="nope">` fails at render time:

```console
mdxr: error: Invalid props: status: Invalid type: Expected ("todo" | "doing" | "done" | "blocked") but received "nope"
```

`mdxr catalog --json` lists project components alongside the built-ins —
`"source": "project"` — so an agent can discover them before writing a doc.
