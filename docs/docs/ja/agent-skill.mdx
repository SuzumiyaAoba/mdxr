mdxr には、エージェント向けのオーサリング指示とコンポーネントリファレンスカタログが含まれています。`mdxr init` はこれらを Codex と Claude 用にインストールし、それぞれのグローバル指示ファイルから参照します。[Agent Skills 形式](https://github.com/vercel-labs/skills)を使う場合は、同梱スキルを `mdxr init --skill` でインストールできます。

## 指示ファイルをインストール

`mdxr init` はデフォルトで Codex と Claude 用の指示をホームディレクトリにインストールします:

```sh
mdxr init                         # ホームディレクトリの Codex + Claude
mdxr init --tool codex            # Codex のみ
mdxr init --tool claude --local   # このプロジェクトの Claude のみ
mdxr init --global                # ホームディレクトリへの導入を明示
mdxr init --force                 # 生成した指示と参照を更新
```

グローバルインストールでは、`$CODEX_HOME/MDXR.md`（`CODEX_HOME` 未設定時は `~/.codex/MDXR.md`）と `$CODEX_HOME/mdxr/references/`、および `~/.claude/` 以下の同等ファイルを作成します。`$CODEX_HOME/AGENTS.md` には Codex 用ファイルを読む指示を追加し、`~/.claude/CLAUDE.md` からは `@./MDXR.md` を読み込みます。`--local` を指定すると、プロジェクト内に `.codex/MDXR.md` と `.claude/MDXR.md` を作成し、ルートの `AGENTS.md` と `CLAUDE.md` から参照します。ローカルインストールでは、ドキュメントとレンダリング済み HTML の保存先 `.mdxr/` も `.gitignore` に追加します。`--force` は生成した指示ファイルと参照を更新し、他の設定内容は保持します。

同じディレクトリに `AGENTS.override.md` がある場合は、生成された Codex の読み込み指示もそちらに追加してください。同じディレクトリの `AGENTS.md` より `AGENTS.override.md` が優先されます。

## Agent Skill をインストール

`--skill` を指定すると、同梱スキルを対応するスキルディレクトリにインストールします:

```sh
mdxr init --skill                         # → .agents/skills/mdxr/
mdxr init --skill --tool claude           # → .claude/skills/mdxr/
mdxr init --skill --tool all --global     # ホームディレクトリに対応スキルをすべて導入
```

スキルのインストール先はデフォルトでプロジェクトです。`--tool` には `agents`（デフォルト）、`claude`、`devin`、`all` を指定できます。ホームディレクトリに入れる場合は `--global` を指定します。`--force` はスキルディレクトリを置き換えます。

リポジトリから [`skills` CLI](https://github.com/vercel-labs/skills) でインストールすることもできます:

```sh
npx skills add Suzumiyaaoba/mdxr --skill mdxr
# グローバルなら -g、特定エージェントを指定するなら -a claude-code
```

## 使い方

どちらかの方式で導入したら、成果物を頼むだけです:

> auth 機能の実装計画を書いて、mdxr で HTML にレンダリングして。

場所を指定しない限り、ドキュメントはリポジトリルートの `.mdxr/` に作成されます — `.mdxr/auth-plan.mdx` は `.mdxr/auth-plan.html` にレンダリングされます。

計画書だけでなく、レポート、レビュー、調査サマリー、リリースノート、ポストモーテムにも使えます。

## スキルの内容

| ファイル | 内容 |
| --- | --- |
| `SKILL.md` | ワークフロー — `.mdx` を書く、`render`、`serve`、`text` — とオーサリングルール、構文チートシート |
| `references/components.md` | カタログ索引: 全コンポーネントの役割をドキュメント種別ごとに整理 |
| `references/components/*.md` | グループ別の詳細ファイル。全シグネチャと例。エージェントは必要なものだけを読む |
| `references/extending.md` | `mdxr.config.ts` でプロジェクト定義コンポーネントを登録する方法 |

スキルは読み取りオンデマンド方式を教えます: エージェントはまず索引を見て、ドキュメントが実際に使う詳細ファイルだけを読み込みます — 計画書を書くのにチャートのリファレンス分のコンテキストコストを払いません。

## エージェントが正確に書ける仕組み

- ドキュメントに JS は書けません — `import`、`{expressions}`、文字列でない属性は `file:line:col` 付きのエラーでレンダリングに失敗し、エージェントが自己修正できます。
- `mdxr catalog --json` が、プロジェクト定義コンポーネントを含む現在のコンポーネントセットをエージェントに提供します。
- `mdxr render --format json` は機械可読なエラーを返し、自動リトライに使えます。
