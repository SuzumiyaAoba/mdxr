`mdxr` is a single CLI for rendering, previewing, and authoring. Run it ad hoc with `npx @suzumiyaaoba/mdxr <command>` or install it globally (`npm i -g @suzumiyaaoba/mdxr`).

## mdxr --version

Print the version of the package resolved by this CLI invocation. `-v` is a shorthand:

```sh
mdxr --version
mdxr -v
```

## mdxr check [path]

Validate one document or every `.md`, `.markdown`, and `.mdx` document in a directory, without writing HTML. The default path is `.mdxr`.

```sh
mdxr check                            # validate .mdxr/
mdxr check plan.mdx                   # validate one document
mdxr check ./reports --format json    # collect structured diagnostics
mdxr check ./reports --strict         # fail on warnings too
mdxr check plan.mdx --render          # also validate project components and rendering
cat plan.mdx | mdxr check -           # explicit stdin input
```

The default check parses documents without evaluating their JavaScript, project configuration, or React components. It checks component names, schema-backed attributes, required attributes, values, prohibited JavaScript, local resources, CodeFile line ranges, Include sections and cycles, citations, and cross references. An unknown attribute such as `sttaus="done"` produces a warning with a suggested spelling. Open-ended component schemas, including shadcn passthrough props, are not treated as closed attribute lists. `aria-*`, `data-*`, and common JSX attributes are allowed.

Missing embedded files and ordinary local links are errors; missing file-reference chips are warnings because plans may refer to files that have not been created yet. External URLs and site-root URLs are not fetched or checked. Markdown link fragments are checked against local headings and explicit IDs. Independent diagnostics are collected from parseable documents, and checking continues after a malformed file. Directory traversal skips build/dependency directories and `.mdxr/history`, and does not follow symbolic links.

`--render` additionally loads the nearest project `mdxr.config.*` and project components, then validates server rendering when static checks have no errors. This option executes trusted project configuration and component code; document JavaScript remains prohibited. It may use the renderer's build cache, but does not write an HTML output file.

| Flag | Description |
| --- | --- |
| `--format <format>` | Diagnostic output: `text` (default), `json`, or `github` |
| `--strict` | Return a failure exit code for warnings as well as errors |
| `--render` | Load project components and additionally validate rendering |

JSON output contains `ok`, `files`, `errors`, `warnings`, and a `diagnostics` array. Each diagnostic has `file`, `line`, `column`, `code`, `severity`, and `message`, plus `suggestion` when available. Errors produce exit code 1; warnings do so only with `--strict`.

## mdxr library [dir]

Browse and search Markdown and MDX documents in a directory. The default directory is `.mdxr`.

```sh
mdxr library                         # browse .mdxr
mdxr library ./docs -p 3738 --open   # browse another directory
```

The library recursively lists `.md`, `.markdown`, and `.mdx` files. A document's title comes from its frontmatter `title`, then its first heading, then its filename. Frontmatter `status` is available as a filter, and the displayed update date comes from the file's modification time.

Search covers each document's title, body, and relative file path. Space-separated terms, including terms separated by a full-width space, use AND matching; for example, `かたろぐ ＡＰＩ`. Japanese text supports partial matches. Unicode NFKC normalization handles full-/half-width forms, including half-width kana with voiced marks; lowercasing makes letter case equivalent, and hiragana and katakana are treated as equivalent. Search does not infer kanji readings or expand synonyms, and it does not perform morphological analysis. During IME composition, the query runs after the input is committed.

Filter by status and sort results by relevance, update date, or title. Results show a nearby text excerpt with matching terms highlighted. Use **Refresh** to re-index additions, edits, and deletions. Choose the interface language manually or let the browser language select Japanese or English. The selected language and System, Light, or Dark theme are saved for this library's browser origin.

Opening a result launches the existing live preview workspace, including its document workspace and version history, in a new tab. `mdxr library` and its previews listen on loopback. Indexing reads document text and frontmatter without executing document JavaScript or project-defined components. It skips `node_modules`, `dist`, `.git`, `.mdxr-cache`, `storybook-static`, and `.mdxr/history`, and does not follow symbolic links. `mdxr serve` uses the same library with optional agent chat and a document path to open directly.

Delete a document from its row to permanently remove only that document file; assets and parent directories remain. Confirm deletion in the UI before the file is removed.

| Flag | Description |
| --- | --- |
| `-p, --port <port>` | Preferred port (default `3737`); if taken, the next free port is used |
| `--open` | Open the library in the default browser once serving |
| `--idle-timeout <seconds>` | Close unused previews after this delay (default `300`; `0` disables automatic shutdown) |

## mdxr render

Render an `.mdx` document — a file argument or stdin — to a standalone HTML file.

```sh
mdxr render plan.mdx                  # → plan.html
mdxr render plan.mdx -o out.html      # custom output path
cat plan.mdx | mdxr render > out.html # stdin → stdout
mdxr render plan.mdx --open           # also open plan.html in the browser
mdxr render plan.mdx --no-hydrate     # static HTML, no client bundle
mdxr render plan.mdx --format json    # machine-readable errors
```

| Flag | Description |
| --- | --- |
| `-o, --out <path>` | Output path. Defaults to `<file>.html`; stdout for stdin input or `-` |
| `--format <format>` | Error output: `text` (default), `json`, or `github` |
| `--no-hydrate` | Emit static HTML without the client hydration bundle |
| `--open` | Open the rendered file in the default browser. Requires an output file |

:::note
Stateful components (`Tabs`, `Accordion`, `Switch`, the kanban `<Board>`, …) hydrate in the browser via an inlined client bundle. The bundle is skipped automatically when a document uses no hydratable components, so pure-Markdown docs stay lean; `--no-hydrate` disables it entirely.
:::

Errors report `file:line:col` so the agent (or you) can fix the source and re-run; `--format json` wraps the same message in machine-readable output.

The rendered HTML includes [review annotations](/annotations): select text or a figure, add comments, and copy Markdown feedback for a coding agent. Annotations work with `--no-hydrate` too.

## mdxr serve

Serve the `.mdxr/` directory and browse all its Markdown and MDX documents. With no path argument, an empty `.mdxr/` is created if needed. Pass another directory to serve it instead. Each document opens in a workspace with live reload.

```sh
mdxr serve                           # .mdxr/ at http://localhost:3737
mdxr serve .mdxr/ --open .mdxr/20260930170000-plan/index.mdx
mdxr serve ./reports -p 8080 --open ./reports/plan.mdx
mdxr serve --open                    # open the directory listing
cat plan.mdx | mdxr serve - --open   # explicit stdin preview
```

| Flag | Description |
| --- | --- |
| `-p, --port <port>` | Preferred port (default `3737`); if taken, the next free port is used |
| `--open [file]` | Open the named document directly, or the directory listing when no file is given |
| `--idle-timeout <seconds>` | Close unused previews after this delay (default `300`; `0` disables automatic shutdown) |
| `--agent <agent>` | Show a local chat panel for `codex` or `claude` |
| `--server <url>` | Codex App Server endpoint; accepts `unix:///absolute/path` or `ws://...` (requires `--agent codex`) |
| `--session <id>` | Send messages to an existing Codex thread (requires `--agent codex`) |

After the last browser tab disconnects, unused previews stop automatically after five minutes, releasing file watchers and agent connections. Active agent turns keep their preview alive. Each unused document preview can expire while the library stays open; selecting it again starts a fresh preview. Use `--idle-timeout <seconds>` to change the delay or `--idle-timeout 0` to disable it. These settings also apply to `mdxr library`. Ctrl+C, SIGTERM, and SIGHUP close the library and all its previews immediately.

The file given to `--open` is resolved from the working directory; absolute paths also work. The browser opens that document directly, and its preview URL includes the file path relative to the served directory. A file argument such as `mdxr serve .mdxr/20260930170000-plan/index.mdx --open` serves the entire containing `.mdxr/` library and selects that file. Files outside `.mdxr/` use their parent directory as the library.

The watcher follows each opened document's render dependencies — a `theme` CSS file and its imports reload the preview too. With `--agent`, every document workspace includes an AI Elements chat panel. Use **Annotate** to add comments to rendered content, then send them directly to the same chat. Documents are rendered and agent sessions are opened when you select them from the library.

The watcher records local MDX versions as files change. Use the version picker to render an earlier version, inspect its **Raw MDX**, or compare it with another version in **Diff**. History is stored under `.mdxr/history/`; capturing and viewing history is local and needs no API token.

Choose **Export HTML**, select the contents, then choose **Download HTML**:

- **Document only** preserves the document's current display and form values, without comments, review controls, conversations, or version records. It does not fetch conversation or history data.
- **Document and review** includes current comments, section review statuses, and answers. Conversations, unsent drafts, comment handoff history, saved MDX versions, and diffs are excluded from both the visible appendix and embedded JSON.
- **All records** is the default and preserves the complete archive: rendered document, conversation, comments, drafts, section reviews, every saved MDX version, and diffs.

Images and stylesheets are embedded in every mode. Export reports an error if it cannot capture an external resource; the HTML opens locally without the server. Press Escape or choose **Cancel** to close the dialog without exporting.

Pass `--agent` to enable chat in the directory's document workspaces. To message a Codex TUI session that is already running, pass its thread ID. By default, mdxr connects to the local Codex daemon socket and queues each message on that thread, leaving the TUI session running:

```sh
mdxr serve .mdxr/ --agent codex --session <thread-id> --open .mdxr/20260930170000-plan/index.mdx
```

Messages appear as queued while Codex is busy. Once Codex processes a message, its reply appears in the MDX preview. To use a specific daemon socket or WebSocket App Server, pass its endpoint with `--server`:

```sh
mdxr serve .mdxr/ --agent codex --server unix:///absolute/path/to/app-server.sock --session <thread-id>
mdxr serve .mdxr/ --agent codex --server ws://127.0.0.1:4500 --session <thread-id>
```

When `--session` is omitted, mdxr uses this document's saved Codex thread ID in `.mdxr/sessions.json`, if one exists. Otherwise, it starts a new thread.

Claude chat uses a long-lived Claude Agent SDK session managed by mdxr:

```sh
mdxr serve .mdxr/ --agent claude --open .mdxr/20260930170000-plan/index.mdx
```

The Claude session is owned by mdxr and does not attach to a session started by an external Claude CLI process. `--session` applies only to Codex.

The preview has no tool-approval UI, so actions that require approval are rejected. Claude runs with the `dontAsk` permission mode.

The document-to-session mapping and conversation history are stored in the working directory's gitignored `.mdxr/sessions.json`. `--agent` works with directory and file paths and does not support stdin. Agent replies are displayed as Markdown; JSX and raw HTML in replies are not executed.

## mdxr text

Render an `.mdx` document to plain Markdown. Every component becomes an ASCII/text stand-in — status checkbox lists, block-bar charts, GFM tables, `<details>` disclosures — so the document stays readable in any Markdown viewer or terminal.

```sh
mdxr text plan.mdx                    # → plan.txt.md
mdxr text plan.mdx -o plan.md         # custom output path
cat plan.mdx | mdxr text > plan.md    # stdin → stdout
```

Interactive-only widgets (dialogs, menus, shadcn chrome) degrade to their text content; unknown components warn to stderr and keep their children.

| Flag | Description |
| --- | --- |
| `-o, --out <path>` | Output path. Defaults to `<file>.txt.md`; stdout for stdin input or `-` |

## mdxr catalog

List the components available to documents — built-ins plus any project-defined components from `mdxr.config.ts`. Agents use `--json` as the machine-readable source of truth for names and attributes.

```sh
mdxr catalog                          # human-readable list
mdxr catalog --json                   # names, meta, and authoring conventions
mdxr catalog --dir ./my-project       # read another project's config
```

| Flag | Description |
| --- | --- |
| `--json` | Print machine-readable JSON |
| `--dir <dir>` | Project directory to read `mdxr.config.ts` from (defaults to cwd) |

## mdxr init

Install mdxr authoring instructions for Codex and Claude, with references from each agent's instruction file. The default installs globally. See [Agent setup](/agent-skill).

```sh
mdxr init                              # Codex + Claude, in your home directory
mdxr init --tool codex                 # Codex only
mdxr init --tool claude --local        # Claude only, in the current project
mdxr init --tool all --local           # Codex + Claude, in the current project
mdxr init --global                     # explicitly install into your home directory
mdxr init --force                      # refresh generated instructions and references
mdxr init --skill                      # install the bundled Agent Skill
```

| Flag | Description |
| --- | --- |
| `--tool <tool>` | Instruction install: `codex`, `claude`, or `all` (default). Skill install: `agents` (default), `claude`, `devin`, or `all` |
| `--local` | Install instructions into the current project instead of your home directory |
| `--global` | Install into your home directory (the default scope) |
| `--force` | Refresh generated MDXR instructions and references, or replace the skill directory with `--skill` |
| `--skill` | Install the bundled Agent Skill instead of the instruction files; skill installs default to the project directory |

The global install creates `$CODEX_HOME/MDXR.md` (or `~/.codex/MDXR.md` if `CODEX_HOME` is unset) and `$CODEX_HOME/mdxr/references/`, plus matching files under `~/.claude/`. It adds an instruction to read the Codex file in `$CODEX_HOME/AGENTS.md`; Claude's `~/.claude/CLAUDE.md` imports `@./MDXR.md`. A local install creates `.codex/MDXR.md` and `.claude/MDXR.md` in the project and references them from the root `AGENTS.md` and `CLAUDE.md`; Claude's `CLAUDE.md` imports `@./.claude/MDXR.md`. It also adds `.mdxr/` to the project's `.gitignore` — skipped when your global git excludes file (`core.excludesFile`, usually `~/.config/git/ignore`) already covers `.mdxr/`. `--force` updates the generated instructions and references while preserving the rest of your agent config files.

The bundled prompts tell the agent to compare their recorded version with `--version` from the CLI used for the task. If they differ, the agent reports both versions and recommends `mdxr init --force` with the same CLI, preserving the original `--tool` and `--local`/`--global` scope; Skill installs also keep `--skill`. See [Agent setup](/agent-skill) for details.
