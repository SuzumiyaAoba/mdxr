:::question
Where does `mdxr render plan.mdx` actually turn MDX into standalone HTML, and
what is on the path?
:::

:::toc
:::

:::answer
`mdxr render` calls <SymbolRef name="renderFile" kind="fn" path="src/render.ts" />,
which delegates compilation to <SymbolRef name="mdxToHtml" kind="fn" path="src/mdx.ts" />
and then inlines the generated Tailwind CSS into a static document shell. No
client runtime is emitted — copy buttons and the ToC work via a single
delegated listener and native `<details>`.
:::

## Execution flow

:::flow{title="mdxr render plan.mdx"}

<FlowStep name="cli()" path="src/cli.ts">
  Parses argv with cac, dispatches to the render command.
</FlowStep>

<FlowStep name="renderFile()" path="src/render.ts">
  Reads the .mdx file, resolves project components from mdxr.config.ts.
</FlowStep>

<FlowStep name="mdxToHtml()" path="src/mdx.ts" lines="70-106">
  Runs the remark plugins (directives, alerts, headings, code-file), then
  evaluates the MDX and produces hast → JSX.
</FlowStep>

<FlowStep name="renderToStaticMarkup()">
  Static React render — components like Callout and Flow become plain HTML.
</FlowStep>

<FlowStep name="writeFile" path="src/render.ts">
  Inlines compiled CSS + the delegated click handler, writes the .html.
</FlowStep>

:::

## Findings

:::findings

<Finding confidence="confirmed" title="Rendering is synchronous">
  <code>mdxToHtml</code> awaits <code>evaluate()</code> and immediately renders
  — there is no async component boundary. Evidence: <FileRef path="src/mdx.ts" lines="70-106" />.
</Finding>

<Finding confidence="confirmed" title="Directives become components">
  <code>:::flow</code> / <code>:::finding</code> containers are rewritten to MDX
  JSX elements before evaluation — see <FileRef path="src/remark/directives.ts" />.
</Finding>

<Finding confidence="inferred" title="No hydration by design">
  Only a delegated click listener is inlined; interactive shadcn primitives can
  therefore render just their initial state.
</Finding>

<Finding confidence="unverified" title="Serve-mode cache invalidation">
  <code>mdxr serve</code> likely recompiles user components on change, but no
  test covers the path yet.
</Finding>

:::

## Hypotheses

:::hypotheses

<Hypothesis status="supported" title="Directives expand before evaluation">
  `:::flow` / `:::findings` containers are rewritten to MDX JSX elements by
  the remark plugin — the renderer never sees directive syntax. Evidence:
  <FileRef path="src/remark/directives.ts" />.
</Hypothesis>

<Hypothesis status="refuted" title="Copy buttons need a client runtime">
  Ruled out — a single delegated click listener is inlined in the document
  shell; there is no hydration. The `hits="0"` search above is the check.
</Hypothesis>

<Hypothesis status="untested" title="mdxr serve watches mdxr.config.ts">
  Plausible, but the watch path has no test coverage yet.
</Hypothesis>

:::
